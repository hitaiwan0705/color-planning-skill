## 這一週在解什麼問題

上週你量了實物。今天回到螢幕，問一個更難堪的問題：

> **你憑什麼相信螢幕上看到的顏色？**

你在螢幕上核准了一個藍色。隔壁同學的螢幕上那個藍偏紫。
教室投影出來偏綠。你們三個看的是同一個檔案。

**沒有校正過的螢幕，不是判斷顏色的工具，只是一台會發光的機器。**

## 一、色彩管理的三個步驟：3C

色彩管理不是一堆軟體設定，是三個可以分別失敗的步驟：

| 步驟 | 在做什麼 | 失敗時的症狀 |
|---|---|---|
| **校正** Calibration | 把裝置帶回一個**已知且可重複**的狀態 | 每次開機顏色都不一樣 |
| **特性化** Characterization | 量測這個狀態下的裝置，建立描述檔 | 有 profile 但不準 |
| **轉換** Conversion | 依描述檔把色彩換到另一個裝置空間 | 轉出來的顏色不如預期 |

### 順序不可顛倒

**校正回答「裝置現在處於什麼狀態」，特性化回答「這個狀態下訊號對應什麼顏色」。**

先特性化再校正，等於先量了一個馬上要被改掉的狀態——描述檔立刻失效。

這是實務上最常見的失誤，而且症狀有欺騙性：
每個設定看起來都對，輸出就是不準，因為錯的是**順序**，不是任何一個設定值。

**推論**：換燈泡、換媒材、重新線性化、韌體更新之後，
原本的描述檔記錄的對應關係已經不成立。要重做特性化。

## 二、從傳播任務決定校色路徑

先回答三個問題，再選工具：這台螢幕用來核准網頁、影片，還是印刷打樣？閱聽人主要在哪類
裝置觀看？核准結果要交給誰重現？同一台螢幕面對不同任務，目標白點、亮度與工作色域可能不同。

> **操作 gate｜上機前由教師現場確認**
> 可用量測器、校色軟體、顯示器是否支援寫入內部 LUT，以及學生帳號能否安裝 ICC profile，
> 均須依現場設備與原廠文件核對。未核對前只做概念、紀錄設計與軟體校正示範；不得把
> software calibration 寫成硬體校色，也不得安排寫入 monitor LUT 的步驟。

本週採用的功能流程是：量測器讀取顯示器色塊 → 軟體調整或建立校正曲線 → 量測裝置響應 →
建立並安裝 OS 層顯示器 ICC profile。若現場設備不足，以教師提供的匿名量測資料完成判讀，
不因此刪除任何概念或證據欄位。

## 三、操作流程

### 前置

1. 依原廠建議讓螢幕達到穩定狀態，並記錄暖機時間
2. 關掉環境的雜散光，避免陽光直射螢幕
3. 螢幕表面清潔，量測頭要能貼合

### 校正

4. 設定目標：白點、亮度、gamma（tone response）
   - **白點**：本課建議 D65；若你的工作流程主要面向印刷，可用 D50，
     但必須在紀錄裡寫出你選了哪一個以及理由
   - **亮度**：依環境照明決定，不是越亮越好。過亮會讓暗部細節在螢幕上看得到、
     印出來卻沒有
5. 執行量測序列，讓軟體逐色塊讀值

### 特性化與安裝

6. 產生 ICC profile，**命名要帶日期與螢幕識別**
   （例如 `DISPLAY-A_D65_120cdm2_20260930.icc`）
7. 安裝成 OS 層的顯示器 profile
8. **驗證**：重測一組驗證色塊，比較實測與 profile 預測的差距

### 為什麼命名這麼囉嗦

一台螢幕會累積很多個 profile。名字叫 `profile1.icc` 的檔案，
三週後沒有人知道它是哪台螢幕、什麼設定、什麼時候做的。
**profile 版本控管是本課的交付欄位之一**，不是龜毛。

## 四、工作色域：另一個常被跳過的決定

校正完螢幕之後，還要決定**檔案要用哪個工作色域**。

| 工作色域 | 適合 | 風險 |
|---|---|---|
| sRGB | 網頁、一般螢幕交付 | 色域小，鮮豔的青綠色裝不下 |
| Adobe RGB | 印刷導向 | 在未管理的環境看會偏灰 |
| Display P3 | 現代螢幕、影片 | 交付對象若只支援 sRGB 會有落差 |

**沒有「最好的」工作色域，只有「與交付對象相符的」工作色域。**
選擇理由必須寫進交付物——這比選哪一個更重要。

## 課堂活動與時間配置

本週共 120 分鐘：15 分鐘確認訊息任務與設備狀態、20 分鐘設定目標條件、35 分鐘校正／
特性化或教師資料集演練、25 分鐘比較校正前後、20 分鐘同儕重作、5 分鐘離站檢核。
以同一組品牌色在「核准用顯示器」與「一般閱聽人螢幕」兩個情境做決策演練：

1. 小組先寫訊息功能與閱聽人裝置假設，再選白點、亮度、tone response 與工作色域。
2. 依操作 gate 完成現場量測；無設備的小組使用同一份教師資料集。
3. 將校正前後畫面分開觀察，記錄色彩功能是否受影響，不以照片判定色準。
4. 交換紀錄；接手者只看文件，判斷能否重建裝置狀態並指出一項傳播風險。

## 學習證據與評量角色

學習證據是：目標條件決策表、量測／驗證紀錄、ICC profile 識別表、工作色域理由，以及
接手者的可重作檢查。照片只記錄流程，不取代量測資料。證據累積到 ASSIGN-03，主要支援
資料與工具輸出一致性、限制與風險揭露兩個向度。

## 學習工作量

本週不另收作業；成果累積到 ASSIGN-03。課內 120 分鐘完成條件決策、量測／替代資料演練、
校正前後比較、同儕重作與離站檢核。課外約 45–60 分鐘完成命名、備份、工作色域理由與 AI 使用揭露。
評量看的是可追溯性、判斷理由與傳播後果，不以特定設備品牌或數值是否「漂亮」評分。

## 失敗條件

- 缺 ICC profile 紀錄 → 未通過
- 未載明工作色域，或未寫選擇理由 → 未通過
- 未查原廠能力就把 software calibration 寫成硬體校色 → 該段作廢
- 現場能力未確認就出現寫入 monitor LUT 的步驟 → 該段作廢
- profile 檔名無法辨識螢幕與日期 → 退回重新命名

## 本週重點整理

1. 校正先建立可重複狀態，特性化再描述訊號與顏色的關係，順序不能顛倒。
2. ICC profile 是具裝置、狀態與日期的證據，不是「已經色準」的保證貼紙。
3. 工作色域應由訊息用途、閱聽人裝置與交付媒介決定，不存在脫離情境的最佳選項。
4. 設備型號未知只阻擋依賴該功能的操作，不阻擋概念、紀錄與替代資料演練。
