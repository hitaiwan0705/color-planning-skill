# W08｜色彩管理 II：轉換、軟打樣、色域對映與複製原理

## 這一週在解什麼問題

螢幕上「看得到」不代表目的媒材「做得出來」。色彩管理不是保證跨媒體完全相同，而是把來源、轉換規則、目的條件與不可複製部分說清楚，讓取捨可以被交接。

---

## 1. 從來源到目的地

ICC 工作流以來源 profile 解讀數值，經 profile connection space（PCS）連到目的 profile。轉換紀錄至少包含：來源 profile、目的 profile、rendering intent、黑點補償設定、軟體版本與轉換時間。

ICC v4 架構與 rendering intent 定義可查閱 [ICC.1:2022 規格](https://www.color.org/specifications/ICC.1-2022-05.pdf)。規格提供四種 intent；選擇哪一種不是口號，要由影像內容與輸出目的決定。

## 2. Rendering intent 是取捨策略

| intent | 主要取捨 | 檢查重點 |
|---|---|---|
| perceptual | 對整體色域進行映射，維持關係感 | 大面積漸層與整體觀感是否合理 |
| relative colorimetric | 以目的白點為基準，色域內盡量維持 | 色域外色是否截斷、品牌色是否偏移 |
| absolute colorimetric | 保留來源白點的模擬關係 | 打樣紙白模擬是否符合任務 |
| saturation | 優先維持鮮明或區辨 | 圖表類別是否清楚、色相是否被犧牲 |

不要先背「照片用 perceptual、logo 用 relative」再停止判斷。同一檔案至少比較兩個合理候選，列出色域外區域與傳播後果。

## 3. 軟打樣能說什麼、不能說什麼

軟打樣是在已建立 profile 的顯示環境中模擬目的輸出。它可支援預測與版本比較，但不能重現紙張觸感、表面光澤、透明／白色墨層、方向性材質、觀看角度與實體照明的全部效果。

軟打樣截圖必須同時顯示目的 profile、intent、紙白／黑墨模擬選項與色域警告狀態。沒有設定資訊的截圖不可作為交付證據。

## 4. 不同媒介的複製限制

- 印刷：墨層、網點、紙白與表面處理共同限制再現。
- 攝影：照明光譜、曝光、感測器與相機 profile 影響輸入。
- 紡織：纖維、染料、織法與方向性改變量測與觀看結果。
- 材質／表面：光澤、粗糙度、透明、螢光與金屬感不由單一 Lab 值完整描述。

這四項是複製鏈的概念地圖，不代表本週已完成各產業製程訓練。若資料沒有來源或設備證據，不把特定製程參數寫成通則。

## 5. 色貌模式為何出現

CIELAB 在指定條件下提供座標，但跨亮度、背景與觀看條件時，「相同座標」不必然帶來相同外貌。色貌模式加入觀看條件，以預測明亮度、彩度感等外貌屬性。本週只建立問題；W12 再分辨各屬性。

相關 CIE 技術文件可由 [CIE Division 1 出版清單](https://www.cie.co.at/technical-work/divisions/division1/division-publication)追查。

## 6. TASK-04 收件

逐筆核對原始量測檔、條件表、兩端 Lab、ΔE00 公式版本與 D50／D65 視覺欄。不能由摘要數字反推缺失的量測條件。

## 本週交付

- 同一測試檔的兩種 rendering intent 軟打樣紀錄
- 一張來源／目的 profile、intent、黑點補償與軟體版本表
- 一份色域外色彩清單，逐項寫出保留、替換或接受偏移的理由
- 一張四類媒介的限制—證據—溝通後果對照表

## 失敗條件

- 軟打樣截圖未顯示目的 profile 或 rendering intent
- 宣稱軟打樣可完全取代實體輸出與標準照明觀察
- 只列 intent 名稱，未比較其對指定影像或 token 的後果
- 將不同媒介的概念差異寫成未附來源的固定製程參數
- TASK-04 數值無法回指原始量測檔
