## 這一週在解什麼問題

期中之前，你學會了一套流程：量測、校色、轉換、軟打樣。那套流程回答的是

> 這兩個顏色一不一樣。

從這週開始，問題換一個。不是顏色一不一樣，是

> **這則訊息，在它會被看見的每一個地方，還在不在。**

這不是同一個問題換句話說。看看差別：

| | 色彩管理的問題 | 傳播的問題 |
|---|---|---|
| 問什麼 | 螢幕上的紅和印出來的紅差多少 | 「這是警告」這件事，在印出來以後還讀不讀得到 |
| 誰判定 | 儀器 | 閱聽人，在他自己的環境裡 |
| 成功長什麼樣 | ΔE00 在容差內 | 功能沒有掉；掉了的地方有替代方案 |
| 失敗的樣子 | 數值超標 | 數值合格，但沒有人看出那是警告 |

**右邊那一欄不能從左邊那一欄推出來。** ΔE00 合格的色，可能在賣場燈下和旁邊的品項糊成一片；
ΔE00 超標的色，可能因為它旁邊有文字標示而完全不影響訊息傳達。

後半學期的七週在做的，是右邊那一欄。左邊那一欄不會消失——它降級成**證據**。
你要用量測數字來支持傳播判斷，而不是拿量測數字代替傳播判斷。

## 一、色彩在一則訊息裡負責什麼

先把話說清楚：色彩在傳播裡不是裝飾，它承擔具體功能。至少五種：

| 功能 | 它在做什麼 | 掉了會怎樣 |
|---|---|---|
| **辨識** | 讓人一眼認出這是誰 | 品牌被認成別人 |
| **區隔** | 把不同類別分開 | 兩個類別被當成同一類 |
| **警示** | 標出需要注意的地方 | 該注意的沒被注意 |
| **層級** | 標出先看哪個、後看哪個 | 閱讀順序亂掉 |
| **情緒定調** | 設定閱聽人的預期 | 訊息語氣被讀錯 |

**同一個色在不同地方可以負責不同功能。** 品牌主色在包裝上負責辨識，
在介面裡可能負責層級。這就是為什麼「品牌色 = #XXXXXX」這一行寫不完一份規範。

### 一個可以判定的寫法

不可判定：

> 主色要呈現專業與信賴感，並保持一致性。

可判定：

> 主色在包裝正面負責**辨識**：在賣場貨架 1.5 公尺距離、下午自然光下，
> 須能與貨架上另外兩個競品區分。判定方法：三位觀察者、隨機順序、各判兩次。

第二種寫法可以被驗證，也可以被推翻。第一種只能被同意。
**規範書要寫第二種。**

## 二、接觸點不是通路清單

「接觸點」不是「官網、DM、包裝」這種列表。那是通路。
**接觸點是三欄的東西：**

| 欄位 | 內容 | 為什麼缺不得 |
|---|---|---|
| **媒介** | 校正過的顯示器／Mimaki 輸出於某媒材／燈箱下的實體展示 | 決定色域上限與可達到的彩度 |
| **觀看條件** | 光源、背景、距離、角度、觀看時長 | 決定人眼實際看到什麼 |
| **色彩空間** | sRGB／Display P3／輸出描述檔 | 決定數值代表什麼 |

**缺任一欄，這個接觸點無法判定失效。** 因為你說「這裡看起來不對」的時候，
沒有人知道你講的是哪一個條件下的事，也沒有辦法重現。

### 本課的三個接觸點

這學期你要處理的三個接觸點是規定的，不是自選：

1. **校正過的顯示器**（W07 建立的 ICC profile，你已經有了）
2. **Mimaki 實體輸出**（W13 印出來）
3. **標準燈箱下的實體展示**（W15 在 D50／D65 下觀察）

選這三個是因為它們的失效機制不同：色域差、媒材差、光源差。
三個都做過，你才會知道規範書要防的是哪一種。

> **設備閘門**
> 本課燈箱具備 D50 與 D65，兩者皆可用。
> 燈箱的螢光燈管種類（CWF／TL84／U30 其一）**未確認**，**不得假設 TL84 存在**；
> 依賴賣場光源的演示一律標 `<!-- BLOCKED: 待設備確認 -->`，本學期不排入評量。
> 本模組的同色異譜觀察限用 D50 與 D65 兩種已確認光源。

## 三、失效的四個機制

接觸點會失效，機制就那幾個。這四個就是後面六週要逐一觀察的對象：

| 機制 | 內容 | 在傳播現場長什麼樣 |
|---|---|---|
| **同色異譜** | 兩個光譜不同的色，某光源下相同、換光源就不同 | 賣場看起來搭，回家不搭 |
| **觀察者差異** | 錐細胞分布與水晶體黃化程度因人而異 | 兩位審稿人對同一張打樣意見相反 |
| **觀察條件** | 光源、背景、視角、周圍亮度 | 燈箱裡對、桌上不對 |
| **適應狀態** | 眼睛會補償，且補償需要時間 | 從戶外進來馬上看，和坐十分鐘後看不一樣 |

### 每一個機制都有一個誘人但錯誤的結論

歸因最常見的失敗不是「找不到原因」，是**跳到一個看起來合理的原因就停下來**：

| 機制 | 要控制的證據 | **不可直接下的結論** |
|---|---|---|
| 同色異譜 | 樣本光譜、D50／D65 分欄紀錄 | 換光源有差就一定是同色異譜 |
| 觀察者差異 | 匿名觀察者代碼、重複判斷 | 少數人的偏好代表所有受眾 |
| 觀察條件 | 背景、距離、角度、順序、時間 | Lab 相近就到處看起來相同 |
| 適應狀態 | 適應光、時間、觀察者自述狀態 | 任何差異都歸因於「眼睛不準」 |

**每筆歸因只選一個目前最有證據的主因**，並寫下排除其餘三項的理由。
證據不足就寫「未能判定」——**這是合格答案，猜一個才是不合格。**

## 四、為什麼觀察對象是你自己的輸出

本模組的觀察基底不是課本圖片，不是老師準備的色票，
是**你自己設計、自己輸出的樣本**。

1. **你知道它應該傳什麼訊息。** 你有原始檔、有 design token、有 W04 的意象決策表。
   功能掉了的時候，你查得到上游。
2. **你要負責修它。** W16 你要根據量測與觀察結果改一版再印。觀察別人的東西，改不到。
3. **這才是傳播的完整迴圈。** 訊息 → 媒介 → 接收 → 回饋 → 修正。
   只做到「印出來」是生產；做到「量、看、改、再印」才是規劃。

## 五、本週實作：接觸點對照表初稿

今天要產出的是 **TASK-09 的第一份文件**，也是後面六週所有觀察掛靠的架構。

### 步驟

1. 選定一則訊息（沿用 W04 的意象決策表，不要另起爐灶）
2. 填完三個接觸點的三欄：媒介、觀看條件、色彩空間
3. 對每個接觸點，寫出色彩在那裡負責哪一項功能（五選一或多選，但要指名）
4. 為每一項功能寫出**判定方法**——像第一節那個「可判定的寫法」
5. 登錄觀察基底的色票（S1）

### S1 觀察基底的選色要求

1. **必須包含 W04 決策表裡的品牌主色**——這樣才連得回傳播目標
2. **必須包含至少一個高彩度色與一個近中性色**——兩者的失效行為不同
3. **必須包含一組「應該相同」的配對**——例如同一個色在不同元素上的用法

沿用 W03 的 design token 表，另加三欄：

| 欄位 | 內容 |
|---|---|
| `touchpoint_ref` | 這個色出現在對照表的哪幾個接觸點 |
| `color_function` | 它在那裡負責哪一項傳播功能 |
| `failure_test` | 用什麼方法判定這項功能掉了 |

**第三欄是這個模組和純技術觀察的分界。**
沒有它，你做的只是色差量測；有了它，你做的是「這個訊息有沒有傳到」。

### 第一組儀器與人眼對照

1. 把觀察基底的色票在螢幕上顯示（螢幕已於 W07 校正）
2. 記錄**完整觀察條件**：光源、背景色、觀察距離、觀察時間、你進入該環境多久
3. 用眼睛判讀並寫下描述（偏紅／偏暗／彩度不足）
4. 用工具取得數值：

```bash
python3 tools/color/scripts/color_audit.py --palette "#色1,#色2,..." --json > W10_audit.json
```

5. 把儀器數值與人眼判讀**並排寫在同一列**，並標出這一列對應哪個接觸點

### 為什麼觀察條件要記到「你進入該環境多久」

適應需要時間。剛從走廊進來就判讀，和坐了十分鐘再判讀，結果可能不同。
不記這一欄，下週你想重現自己的觀察都做不到。

### 這一週不要求你解釋失效

本週只要求記錄與架構。**歸因從 W11 才開始**，因為你還沒學到機制。
現在就急著解釋，會得到一堆「因為光線問題」這種等於沒說的句子。

它打包三份證據規格：**TASK-05**（W07–W09 已完成的顯示器校正與軟打樣）、
**TASK-07**（感知落差資料的前段）與 **TASK-09**（跨接觸點色彩規範）。

本週不收件。本週要產出、自行保管到 W13 的：

- 接觸點—訊息—色彩功能對照表初稿：三個接觸點、三欄填滿、每項功能附判定方法
- 觀察基底的 design token 表，含 `touchpoint_ref`、`color_function`、`failure_test` 三欄
- 觀察條件紀錄：光源、背景色、觀察距離、觀察時間、進入該環境的時間長度
- 人眼判讀描述，與儀器數值並排，並標出對應的接觸點
- `color_audit.py` 的 JSON 輸出檔
- AI 使用揭露

## 失敗條件

- 接觸點少於三個 → ASSIGN-03 未通過（不是扣分）
- 接觸點三欄任一欄留白 → 該接觸點不成立，無法用它主張失效
- 色彩功能只寫「好看」「符合品牌調性」而無判定方法 → 該項不採計
- 觀察條件缺任一欄 → 該筆紀錄不成立
- 只有人眼判讀而無儀器數值，或只有數值而無觀察條件 → 該筆不採計
- `color_function` 欄留白 → 退回；這一欄是本模組與純量測的分界
- 本週就寫歸因結論 → 不扣分，但該結論不採計（機制尚未講授）
- 色票缺唯一 ID、色彩空間、profile 或功能欄 → 該筆不成立
- 把偏好或少數觀察者結果寫成閱聽人通則 → 該主張作廢
