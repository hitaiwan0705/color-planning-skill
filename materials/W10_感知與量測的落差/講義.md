## 這一週在解什麼問題

期中之前，你學會了一套流程：量測、校色、轉換、軟打樣。那套流程的前提是

> 儀器給的數字可以代表顏色。

現在要拆掉這個前提。真實的傳播現場長這樣：

- 客戶在會議室看打樣說「這個紅太暗」，你拿量測報告說「ΔE00 在容差內」。**兩邊都沒錯。**
- 網拍賣家的商品照在賣場燈下拍，買家在家裡日光燈下看，退貨理由寫「色差」。
- 你的品牌主色在手機上、在印刷品上、在展場燈光下，是三個不同的顏色，
  但**品牌手冊上只有一組數值**。

這些都不是儀器失準。它們是**同一個問題的三個面貌**：

> **儀器量的是刺激，人看到的是知覺。兩者之間隔著觀察條件與觀察者。**

後半學期的七週，就是在建立處理這個落差的能力。而且不是紙上談兵——
你會對著自己印出來的樣本做。

## 一、落差的四個來源

儀器判定相同、人眼判定不同，主要來自四處：

| 來源 | 機制 | 典型現場 |
|---|---|---|
| **同色異譜** | 兩個光譜不同的色，在某光源下相同、換光源就不同 | 賣場看起來搭，回家不搭 |
| **觀察者差異** | 每個人的錐細胞分布與水晶體黃化程度不同 | 兩位審稿人對同一張打樣意見相反 |
| **觀察條件** | 光源、背景、視角、周圍亮度 | 燈箱裡對、桌上不對 |
| **適應狀態** | 眼睛會補償，且補償需要時間 | 從戶外進來馬上看，和坐十分鐘後看不一樣 |

### 每一個來源都有一個誘人但錯誤的結論

歸因最常見的失敗不是「找不到原因」，是**跳到一個看起來合理的原因就停下來**：

| 來源 | 要控制的證據 | **不可直接下的結論** |
|---|---|---|
| 同色異譜 | 樣本光譜、D50／D65 分欄紀錄 | 換光源有差就一定是同色異譜 |
| 觀察者差異 | 匿名觀察者代碼、重複判斷 | 少數人的偏好代表所有受眾 |
| 觀察條件 | 背景、距離、角度、順序、時間 | Lab 相近就到處看起來相同 |
| 適應狀態 | 適應光、時間、觀察者自述狀態 | 任何差異都歸因於「眼睛不準」 |

**每筆歸因只選一個目前最有證據的主因**，並寫下排除其餘三項的理由。
證據不足就寫「未能判定」——**這是合格答案，猜一個才是不合格。**

**歸因是本模組的核心技能。** 說「不一樣」誰都會，
說「不一樣是因為這四者中的哪一個，而且我排除了其他三個」才是能力。

> **設備閘門**
> 本課燈箱具備 D50 與 D65，兩者皆可用。
> 燈箱的螢光燈管種類（CWF／TL84／U30 其一）**未確認**，
> **不得假設 TL84 存在**；依賴賣場光源的同色異譜演示一律標
> `<!-- BLOCKED: 待設備確認 -->`，本學期不排入評量。
> 本模組的同色異譜觀察限用 D50 與 D65 兩種已確認光源。

## 二、為什麼要用「自己的輸出」當觀察對象

本模組的觀察基底不是課本圖片，不是老師準備的色票，
是**你自己設計、自己輸出的樣本**。

理由有三個：

1. **你知道它應該是什麼顏色。** 你有原始檔、有 design token、有軟打樣紀錄。
   落差出現時，你查得到上游。
2. **你要負責修它。** W16 你要根據量測與觀察結果改一版再印。
   觀察別人的東西，改不到。
3. **這才是傳播的完整迴圈。** 訊息 → 媒介 → 接收 → 回饋 → 修正。
   只做到「印出來」，那是生產；做到「量、看、改、再印」，才是規劃。

TASK-06（虛實輸出鏈）與 TASK-07（感知落差資料集）**共用同一組樣本**，
但分開計分：前者評輸出鏈的完整與可追溯，後者評觀察與歸因。
**任一方缺件，兩方皆不成立**——避免「印出來了但沒觀察」
或「觀察了但拿不出輸出鏈證據」各拿一半分數。

## 三、S1 觀察基底的設計登錄

今天要決定並登錄的，是接下來七週你要盯著看的那組色。

### 選色的三個要求

1. **必須包含你 TASK-03 的品牌主色**——這樣才連得回傳播目標
2. **必須包含至少一個高彩度色與一個近中性色**——兩者的落差行為不同
3. **必須包含一組「應該相同」的配對**——例如同一個色在不同元素上的用法

### 登錄欄位

沿用 W03 的 design token 表，另加三欄：

| 欄位 | 內容 |
|---|---|
| `observation_role` | 這個色在觀察裡的角色（主色／高彩度對照／中性對照／配對組） |
| `expected_use` | 它最終要出現在什麼媒介上 |
| `communication_intent` | 它要傳達什麼訊息（連回 TASK-03 的意象決策表） |

**第三欄是這個模組和純技術觀察的分界。**
沒有它，你做的只是色差量測；有了它，你做的是「這個訊息有沒有傳到」。

## 四、P1：第一組對照怎麼做

### 步驟

1. 把觀察基底的色票在螢幕上顯示（螢幕已於 W07 校正）
2. 記錄**完整觀察條件**：光源、背景色、觀察距離、觀察時間、你進入該環境多久
3. 用眼睛判讀並寫下描述（偏紅／偏暗／彩度不足）
4. 用工具取得數值：

```bash
python3 tools/color/scripts/color_audit.py --palette "#色1,#色2,..." --json > P1_audit.json
```

5. 把儀器數值與人眼判讀**並排寫在同一列**

### 為什麼觀察條件要記到「你進入該環境多久」

適應需要時間。剛從走廊進來就判讀，和坐了十分鐘再判讀，結果可能不同。
不記這一欄，下週你想重現自己的觀察都做不到。

### 落差紀錄的五個步驟

1. 先寫一個**可檢驗的問題**，例如「灰背景改成深藍後，判讀是否把 T03 判得更亮？」
2. 固定樣本與呈現順序，**只改一個條件**
3. 分欄記錄儀器數值、人眼判讀與觀察條件
4. 用**事件 ID** 連到工具輸出或 i1 Pro 原始檔
5. 寫主因、排除理由，以及本筆資料的限制

事件 ID 是後面六週能不能互相對照的關鍵。沒有它，P7 要回頭比對時會找不到對應。

### 這一週不要求你解釋落差

P1 只要求記錄。**歸因從 P2 才開始**，因為你還沒學到機制。
現在就急著解釋，會得到一堆「因為光線問題」這種等於沒說的句子。

本週的進度交件 **P1**：

- 觀察條件紀錄：光源、背景色、觀察距離、觀察時間、進入該環境的時間長度
- 人眼判讀描述，與儀器數值並排
- `color_audit.py` 的 JSON 輸出檔
- AI 使用揭露

## 失敗條件

- 觀察條件缺任一欄 → 該筆紀錄不成立
- 只有人眼判讀而無儀器數值，或只有數值而無觀察條件 → 該筆不採計
- `communication_intent` 欄留白 → 退回；這一欄是本模組與純量測的分界
- P1 就寫歸因結論 → 不扣分，但該結論不採計（機制尚未講授）
- 色票缺唯一 ID、色彩空間、profile 或訊息角色 → 該筆不成立
- 把偏好或少數觀察者結果寫成閱聽人通則 → 該主張作廢
