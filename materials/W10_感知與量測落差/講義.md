# W10｜感知與量測的落差、觀察基底登錄

## 這一週在解什麼問題

兩個樣本的量測值接近，人眼仍可能判成不同；反過來，數值不同也可能未改變訊息判讀。本週不把人眼或儀器選成唯一裁判，而是建立一份能追查落差來源的共同資料。

## 一、四個候選來源

| 來源 | 要控制的證據 | 不可直接下的結論 |
|---|---|---|
| 同色異譜 | 樣本光譜、D50／D65 分欄 | 換光源有差就一定是同色異譜 |
| 觀察者差異 | 匿名觀察者代碼、重複判斷 | 少數人的偏好代表所有受眾 |
| 觀察條件 | 背景、距離、角度、順序、時間 | Lab 相近就到處看起來相同 |
| 適應狀態 | 適應光、時間、自述狀態 | 任何差異都歸因於眼睛不準 |

每筆歸因只選一個目前最有證據的主因，並寫下排除其餘三項的理由；證據不足就標「未能判定」。

## 二、P1：建立觀察基底

本模組沿用之後要實體輸出的同一組色。先完成 S1 登錄：token ID、色彩空間、數值、來源／工作 profile、設計檔座標、訊息角色與預定媒材。每個色都要回答「它在傳播上負責什麼」，例如識別、警示、層級或狀態；「好看」不是角色。

同一組樣本供 TASK-06 輸出鏈與 TASK-07 感知觀察共用，但兩份任務分開提交、分開評分。

## 三、落差紀錄格式

1. 先寫可檢驗問題，例如「灰背景改成深藍後，受測者是否把 T03 判得更亮？」
2. 固定樣本與呈現順序，只改一個條件。
3. 分欄記錄儀器數值、人眼判讀與觀察條件。
4. 用事件 ID 連到工具輸出或 i1 Pro 原始檔。
5. 寫主因、排除理由與本筆資料的限制。

涉及 ΔE00 時註明 CIEDE2000；現行定義見 [ISO/CIE 11664-6:2022](https://www.cie.co.at/publications/colorimetry-part-6-ciede2000-colour-difference-formula-1)。

## 本週交付

- P1 色票／token 登錄表，含訊息角色、色彩空間與 profile
- 一張感知落差對照表，至少一筆同時有人眼與儀器欄
- TASK-06、TASK-07 的共同樣本 ID 清單與分開交件路徑
- 一段主因與三項排除理由；證據不足者標「未能判定」

## 失敗條件

- 色票缺唯一 ID、色彩空間、profile 或訊息角色
- 只有人眼判讀或只有儀器數值，未能形成成對紀錄
- 歸因列出多個機制卻沒有排除理由
- 把偏好或少數觀察者結果寫成閱聽人通則
- 使用未確認的螢光燈管作為必要條件
