## 本週學習目標

完成本週後，你應能：

1. 將「亮、深、濃、淡、重」等需求語拆成指定屬性、比較對象與觀看條件。
2. 分辨 lightness、brightness、chroma、saturation 與 colorfulness，不用一個中文詞代替多個量。
3. 比較兩種環境條件下的外觀紀錄，將儀器座標與知覺屬性分欄。
4. 把需求翻譯成下一位執行者可操作、可驗證且能回指訊息功能的規格。

## 這一週在解什麼問題

你把打樣拿給客戶，他說：**「這個顏色太重了。」**

「重」是什麼意思？

- 太暗？
- 太鮮豔？
- 面積太大？
- 在那個環境下看起來太突出？

**這四件事的修法完全不同，而且互相衝突**：把它調亮會讓彩度看起來下降，
把彩度降下來又可能讓它在版面上消失。

如果你不能把客戶那句話翻譯成具體的哪一個量，你就只能瞎改。
改三次都沒改對，客戶會覺得你不專業——**問題其實出在第一句話沒有被正確拆解。**

**本週要建立的能力**：把模糊的色彩描述，拆成可以分別記錄、分別修正的欄位。

### 這是傳播工作，不是量測工作

需求語不是雜訊，是**閱聽人與客戶唯一會用的語言**。他們不會說「彩度降兩階」，
他們會說「太重了」。規範書的價值，就在於它把這句話變成一個下次不用重猜的欄位。

| 誰說的 | 原話 | 規範書要寫成 |
|---|---|---|
| 客戶 | 「這個紅太重了」 | 主色在包裝正面的**彩度**欄，較 W10 基準降一階；明度欄不動 |
| 業務 | 「印出來沒有螢幕上好看」 | 實體接觸點的**明亮度**欄下降；屬環境亮度造成，非輸出偏差 |
| 使用者測試 | 「看不出哪個是重點」 | **層級**功能失效；肇因為明度差不足，非色相問題 |

右欄可以交給下一個人執行，左欄不行。**這一欄一欄的翻譯，就是這週的實作。**

## 一、中文在這裡的詞彙比需要的少

這是實務上真正的難點：**同一個中文詞會對應到好幾個不同的量。**

| 你聽到的詞 | 可能指的是 |
|---|---|
| 「亮」 | 物理上的光強度？還是看起來的明亮程度？還是相對於白的明度？ |
| 「深」 | 明度低？還是彩度高？ |
| 「濃」 | 彩度高？還是墨量多？ |
| 「淡」 | 明度高？還是彩度低？ |

**先建立兩把刀**，其他的都掛在這兩把刀上：

### 第一把：物理量 vs 知覺量

- **物理量**：儀器量得到、有單位。例如光的強度
- **知覺量**：只能問人、沒有單位。例如「看起來多亮」

儀器給你物理量，客戶給你知覺量。**兩者不會自動對應。**

### 第二把：絕對量 vs 相對量

- **絕對量**：燈開得越亮，它就越大
- **相對量**：除以參考白之後的比值，燈變亮它不變

同一張紙，在明亮的房間和昏暗的房間，**絕對量差很多，相對量幾乎不變**。
你在燈箱裡看和在教室裡看，變的是絕對量。

## 二、記錄時要分欄的五個欄位

本課要求在觀察紀錄裡把下列各項**分欄登錄**，不得互相代替：

| 欄位（保留英文術語） | 判斷核心 | 比較方式 |
|---|---|---|
| lightness 明度 | 相對於同條件下的白，看起來多明／多暗 | **相對量** |
| brightness 明亮度 | 這個刺激看起來發出或反射多少光 | **絕對外貌量** |
| chroma 彩度 | 相對於同樣照明下的白，有彩程度多少 | **相對量** |
| saturation 飽和度 | 相對於它自己的明亮度，有彩程度多少 | **比率性外貌量** |
| colorfulness 色彩豐富度 | 看起來含有多少有彩成分 | **絕對外貌量** |

> **中文譯名在不同教材裡並不一致。** 交件時**保留英文術語**，
> 並寫下你採用的操作定義。這比爭論哪個中文譯名「正確」有用。
>
> 色相（hue）是另一個維度，與上列五項並列記錄，不佔其中的欄位。

**注意 relative／absolute 的分界**：lightness、chroma 是相對量（除以參考白，
換一盞燈不太變）；brightness、colorfulness 是絕對量（燈變亮它們就變大）。
你在燈箱裡看和在教室裡看，變的主要是絕對量那一組。

**為什麼要分這麼細**：因為修正動作不同。
明度不足要改的是階調；彩度不足要改的是色料或色域；
飽和度的問題常常是**明度太高把彩度稀釋了**——那時降明度反而讓它看起來更鮮豔。

### 本週的主要失分點

交件時寫「這個色偏深」而不分欄。這種描述無法轉成修正動作，
下一位接手的人看不懂你在說什麼。**逐欄登錄，不接受單一「顏色深淺」帶過。**

## 三、色貌現象：同一組數值，不同的看起來

色貌現象指的是：**XYZ 沒變，但看起來變了。**
以下四類最常在跨媒體工作中出現。

| 現象 | 有條件的觀察趨勢 | 你會在哪裡遇到 |
|---|---|---|
| Hunt effect | 在特定適應與照度範圍內，提高適應亮度常使色彩看起來更豐富 | 展場調亮後，原本合適的色彩可能顯得過強 |
| Stevens effect | 在特定觀看條件下，提高亮度可能增強知覺明暗對比 | 顯示器亮度與周圍光改變後，階調關係被重讀 |
| 色適應不完全 | 光源色與適應程度共同改變表面色外觀，方向不能只靠色溫猜 | 暖光、混合照明或缺乏參考白的展示環境 |
| Bezold–Brücke hue shift | 對部分高彩度自發光刺激，亮度改變可能伴隨色相偏移 | 舞台燈或發光介面的調光情境 |

這些是受刺激種類、亮度範圍、背景與適應狀態限制的趨勢，不是每一個樣本都必然出現的定律。
本週活動的目的是留下條件與觀察，不是先把現象名稱套到資料上。

### 數值座標不等於外貌詞

CIELAB 的 L\* 與 C\*ab 是**在指定參考條件下**的座標。
**不能直接把 L\* 當作任何觀看條件下的 brightness**，也不能把 C\*ab 當作 colorfulness。

跨媒體比較時，至少要記：白點、環境亮度、背景、以及該媒介是**發光**還是**反射**。
少了這四項，兩個 Lab 值放在一起比較沒有意義。

### 這一節與規範文件的關係

**品牌規範只寫一組數值是不夠的。**
它至少要同時寫出：適用的觀察條件、可接受的偏移範圍、以及不同接觸點的變體規則。

W13 之後你會親自碰到這件事：同一組 token，
在螢幕上、在實體輸出的樣本上、在燈箱不同光源下，是不同的樣子。

> 本節的模型層（色貌模型如何以數學預測這些現象）**不在本課範圍**。
> 本課只到「知道有這些現象、能在紀錄中把它們分開」。
> iPAS 科目三 L13307 只要求概念層，W08 已講；
> 想深入的可循 W09 自習清單。

## 四、本週實作：需求語翻譯與五欄登錄

### 這一週要新增什麼

回到你的觀察基底，對每一個色**逐欄登錄五個屬性**，並在兩種環境亮度下各做一次。

| 步驟 | 內容 |
|---|---|
| 1 | 燈箱正常亮度下，五欄逐一登錄 |
| 2 | 降低環境亮度（或改用較暗的觀察環境），重做一次 |
| 3 | 標出哪幾欄改變了、哪幾欄沒變 |
| 4 | 對照儀器數值：數值變了嗎 |

**預期你會發現**：儀器數值幾乎沒變，但你的「明亮度」與「彩度」欄改變了。
這正是色貌現象的直接證據，而且是你自己量出來的。

### 歸因格式（延續 W11）

```
現象：色票 C 在降低環境亮度後，彩度欄由「中」降為「低」，明度欄不變。
歸因：環境亮度改變彩度感（絕對量變化，相對量不變）。
排除：
  - 非光源色偏——兩次皆使用同一個已確認光源模式與設備 ID
  - 非適應不足——兩次皆停留十分鐘以上
  - 非量測誤差——儀器數值兩次差異在重複量測的離散範圍內
```

---

### 需求語翻譯表

另外交一張表。左欄放**三句真實的需求語**——來自 W04 的意象決策表、
同學互評、或你自己看樣本時脫口而出的那句話。右欄逐句翻譯：

| 欄位 | 內容 |
|---|---|
| 原話 | 一字不改地抄下來 |
| 指定屬性 | lightness／brightness／chroma／saturation／colorfulness，五選一或多選 |
| 比較對象 | 比誰重、比誰亮——沒有對象的形容詞無法執行 |
| 觀看條件 | 這句話是在什麼條件下說的 |
| 影響的接觸點與功能 | 對照 W10 的表 |
| 可執行的改法 | 一句話，下一個人照著做得出來 |

**「比較對象」欄是最常留白的一欄，也是最關鍵的一欄。**
「太重」如果沒有比較對象，它就只是一個感受，不是一個規格。

## 課堂活動與時間配置

本週以「需求訪談—翻譯—反向確認」完成 120 分鐘活動：

1. 20 分鐘：以案例示範日常語、色貌屬性與傳播需求之間的翻譯邊界。
2. 20 分鐘：兩人一組，一人只用日常語描述自己的樣本，另一人不得先給術語。
3. 30 分鐘：把三句原話填入需求語翻譯表，補指定屬性、比較對象與觀看條件。
4. 30 分鐘：固定樣本與光源，只改周圍亮度或背景，完成兩條件五欄觀察。
5. 20 分鐘：把規格交回原說話者反向確認；若對方不認同，保留第一版並記錄修訂原因。

> **操作 gate｜依現場條件選工具**
> 光源、燈箱或量測設備未確認時，以教師提供的兩組條件資料或既有樣本完成比較；不得把
> 模擬資料寫成自己的實體觀察。設備差異只改變操作方式，不刪除需求翻譯與證據欄位。

## 六、術語稽核

交換紀錄表，把每個「亮、深、鮮、灰、濃」圈出來，
改寫成 **指定屬性 ＋ 比較對象 ＋ 觀看條件** 三段式。

若資料不足以判定是哪一個屬性，寫「本條件無法區分」——
**不要硬選一個術語**。硬選會讓後面六週的資料建立在錯誤的分類上。

## 本週交付

**本週不收件。** ASSIGN-03 的觀察階段，紀錄自行保管到 W13。

- **需求語翻譯表**：至少三句原話，六欄填滿
- 觀察基底每一色的五欄屬性登錄，在兩種環境亮度下各一份
- 標出哪幾欄改變、哪幾欄未變
- 對應的儀器數值，說明數值是否改變
- 至少兩筆色貌現象的歸因，附排除理由
- AI 使用揭露

## 失敗條件

- 五欄未分開登錄，或以單一描述代替 → 退回重做
- 用同一個「亮度」欄同時代替 lightness 與 brightness → 退回
- 把 L\* 直接宣稱為任何觀看條件下的明亮度 → 該主張作廢
- 跨媒體比較未記白點、背景或發光／反射性質 → 該筆不採計
- 用軟打樣結果冒充已完成的實體觀察 → 該筆作廢
- 本週紀錄無法回指 W10 的 token ID → 退回
- 需求語翻譯表的「比較對象」欄留白 → 該句不採計；沒有對象的形容詞不是規格
- 翻譯表的「可執行的改法」寫成「再調整看看」 → 該句退回
- 只做一種環境亮度 → 未達本週要求
- 未附儀器數值對照 → 該筆不採計
- 歸因未附排除理由 → 該筆不採計

## 本週重點整理

1. 需求語是閱聽人與客戶的有效資料，但必須拆成屬性、比較對象與觀看條件才能執行。
2. Lightness／chroma 是相對於參考白的外觀屬性；brightness／colorfulness 是絕對外觀屬性。
3. CIELAB 座標在指定條件下描述色度，不能直接替代跨觀看條件的 brightness 或 colorfulness。
4. 好規格能讓下一位執行者照著修改並驗證，且說得出影響哪個接觸點與訊息功能。
