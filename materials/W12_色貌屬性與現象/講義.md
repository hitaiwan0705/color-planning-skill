# W12｜色貌屬性與色貌現象

## 這一週在解什麼問題

「這個顏色比較亮」在跨螢幕、印刷與空間溝通中太含糊。它可能指物體相對白的明度，也可能指發光刺激的明亮度。本週建立分欄語言，讓觀察者與製作者不必猜同一個字。

## 一、五個欄位

| 屬性 | 判斷核心 | 比較方式 |
|---|---|---|
| lightness 明度 | 相對於同條件白色，看起來多明／暗 | 相對量 |
| brightness 明亮度 | 刺激看起來發出或反射多少光 | 絕對外貌量 |
| chroma 彩度 | 相對於同樣照明白的有彩程度 | 相對量 |
| saturation 飽和度 | 相對於自身明亮度的有彩程度 | 比率性外貌 |
| colorfulness 色彩豐富度 | 看起來有多少有彩成分 | 絕對外貌量 |

中文教材的譯名可能不同，提交時保留英文術語並寫操作定義。不要用單一「顏色深淺」欄替代五欄。

## 二、數值座標不等於外貌詞

CIELAB 的 L\* 與 C\*ab 是指定參考條件下的座標，不能直接當作所有觀看條件下的 brightness 與 colorfulness。跨媒體比較時，至少記錄白點、環境亮度、背景與媒介是發光或反射。

色貌模型的目的，是把觀看條件納入預測；本週不要求背完整模型公式，而要求指出哪個觀看條件使只看 Lab 不夠。CIE 色貌相關出版物見 [Division 1 publication list](https://www.cie.co.at/technical-work/divisions/division1/division-publication)。

## 三、跨媒體對照

用同一 token 的螢幕版與印刷／預定輸出版做兩欄紀錄：媒介、白點、環境、背景、五項外貌描述、訊息角色是否維持。沒有實體輸出者可先用 W08 軟打樣，但必須把結果標為預測，不能冒充樣本觀察。

## 四、P3：術語稽核

交換紀錄表，把每個「亮、深、鮮、灰、濃」圈出來，改寫為指定屬性＋比較對象＋觀看條件。若沒有足夠資料判定，寫「本條件無法區分」，不硬選術語。

## 本週交付

- P3 五項色貌屬性分欄表
- 一份螢幕與反射媒介的觀看條件對照
- 三句由含糊形容詞改寫成屬性、比較對象與條件的紀錄
- 一段說明 Lab 座標在本案例不能回答哪個外貌問題

## 失敗條件

- 用同一個「亮度」欄代替 lightness 與 brightness
- 把 L\*直接宣稱為任何觀看條件下的明亮度
- 跨媒體比較未記白點、背景或發光／反射性質
- 用軟打樣結果冒充已完成的實體觀察
- P3 記錄無法回指 P1 的 token ID
