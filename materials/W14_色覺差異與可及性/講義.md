# W14｜色覺差異與可及性

> **狀態：草案。**

---

## 這一週在解什麼問題

一張疫情期間的疫苗預約網頁：可預約的時段是綠色，已額滿是紅色，
沒有任何文字標示。**約 5% 的男性使用者看不出差別。**

這不是美感問題，是**訊息傳不到**的問題。而且它不會出現在任何一份設計評審意見裡，
因為評審室裡的人多半看得見。

**本週要建立的能力**：在交件之前就知道你的訊息對誰傳不到，並且有辦法修。

---

## 一、色覺差異不是「色盲」

常見誤解是「色盲看到黑白」。**絕大多數不是。**
最常見的類型是紅綠區辨能力較弱，藍黃相對正常。

| 類型 | 大致影響 |
|---|---|
| 紅色系感受較弱（protan） | 紅色看起來較暗，紅綠不易分 |
| 綠色系感受較弱（deutan） | 紅綠不易分，最常見 |
| 藍色系感受較弱（tritan） | 藍黃不易分，較罕見 |

還有一種常被忽略的情境：**灰階**。
文件被黑白影印、螢幕截圖被轉成灰階、電子紙裝置——
這些不是色覺差異，但後果相同。

## 二、用數字看你的配色

本課工具可以模擬四種情境。以下是實際跑出來的結果
（來源：`color_audit.py --palette` 輸出，門檻 ΔE00 = 10.0）。

### 案例 A：常見的「紅綠藍黃」四色

色票：`#D32F2F`（紅）、`#388E3C`（綠）、`#1976D2`（藍）、`#FBC02D`（黃）

| 情境 | 最接近的一對 | ΔE00 | 判定 | 混淆對數 |
|---|---|---|---|---|
| 一般 | 綠／黃 | 40.19 | 可區辨 | 0 |
| protan | 紅／綠 | 17.17 | 可區辨 | 0 |
| **deutan** | **紅／綠** | **5.05** | **混淆** | **1** |
| tritan | 綠／藍 | 11.34 | 可區辨 | 0 |
| **灰階** | **紅／藍** | **1.98** | **混淆** | **3** |

**看灰階那一列：四個顏色裡有三對會混淆。**
這組配色在彩色螢幕上完全沒問題，影印之後幾乎全毀。

### 案例 B：色盲友善色票

色票：`#0072B2`、`#D55E00`、`#009E73`、`#CC79A7`

| 情境 | 最接近的一對 | ΔE00 | 判定 |
|---|---|---|---|
| 一般 | 橙／粉 | 37.02 | 可區辨 |
| protan | 藍／粉 | 12.26 | 可區辨 |
| deutan | 綠／粉 | 16.11 | 可區辨 |
| tritan | 藍／綠 | 12.07 | 可區辨 |
| **灰階** | **綠／粉** | **2.73** | **混淆** |

**這一組在三種色覺差異情境下全部通過，但灰階仍然混淆。**

這是本週最重要的一個發現：**色盲友善 ≠ 灰階友善**。
很多人以為選了「無障礙色票」就安全了。沒有——
只要你的東西可能被影印、被截圖轉灰、被電子紙顯示，就還要再檢查一次。

## 三、對比與「僅以顏色傳達」是兩個獨立的問題

這是本課反覆強調、而且**最常被交件者搞混**的一點。

| 問題 | 在問什麼 | 怎麼檢查 |
|---|---|---|
| 對比是否足夠 | 前景與背景的明度差夠不夠讀 | 工具算對比度 |
| 是否僅以顏色傳達 | 拿掉顏色之後，訊息還在嗎 | **人工檢核，工具測不到** |

**通過對比檢查不等於通過「僅以顏色傳達」的檢查。**

一個必填欄位用紅色邊框標示，對比度可能很好，
但如果**唯一**的標示方式就是那個顏色，色覺差異的使用者仍然收不到訊息。

### 冗餘編碼：一個訊息至少兩個線索

修法不是換顏色，是**加線索**：

| 情境 | 只有顏色 | 加上冗餘 |
|---|---|---|
| 表單錯誤 | 紅框 | 紅框 + 錯誤圖示 + 文字說明 |
| 圖表類別 | 四種顏色的線 | 顏色 + 線型 + 直接標註 |
| 狀態指示 | 紅／綠燈 | 顏色 + 形狀 + 文字 |
| 地圖分級 | 色階 | 色階 + 圖樣 + 數值標籤 |

**直接標註（把標籤放在資料旁邊）幾乎總是勝過圖例。**
圖例要求讀者在圖例和資料之間來回比對顏色——那正是色覺差異者做不到的事。

## 四、工具怎麼用

```bash
# 一組色票在五種情境下的可區辨性
python3 tools/color/scripts/color_audit.py --palette "#色1,#色2,#色3" --json

# 一對前景／背景的對比度與色覺模擬後對比
python3 tools/color/scripts/color_audit.py --pair "#前景" "#背景" --json
```

### 判讀規則

1. **只引用工具實際回傳的欄位值**，不改寫、不四捨五入後當原值
2. `wcag.ratio` 與 `cvd_contrast` 是不同問題，通過前者不代表通過後者
3. **「僅以顏色傳達」工具不檢測**，必須另以人工檢核表記錄
4. 工具的 CIEDE2000 目前只通過 7/34 條參照測試，
   **課堂使用可以，不得宣稱完整驗證，不得用於研究等級主張**

## 五、TASK-01：色彩知覺風險稽核

本週發放 TASK-01，W16 收件。它與 P5 共用 W13 的輸出樣本與其原始版面。

### 要交什麼

一份風險表，逐條列出你的版面中可能傳不到的地方：

| 欄位 | 內容 |
|---|---|
| 位置 | 截圖座標或色票 ID |
| 風險類型 | 對比不足／色覺差異混淆／僅以顏色傳達／灰階失效 |
| 證據 | 工具輸出的欄位值 |
| 影響的訊息 | 這個風險會讓什麼訊息傳不到 |
| 修正建議 | 具體動作 |

**「影響的訊息」欄不得留白。** 沒有它，這份表就只是一份技術檢查，
不是傳播稽核——你要說的是「誰收不到什麼」，不只是「這裡對比不足」。

- 工具版本紀錄與對應的 token ID
- AI 使用揭露

## 失敗條件

- 以對比度數值宣稱已滿足「僅以顏色傳達」的檢核 → 該段作廢
- 未做灰階情境檢查 → 未達本週要求
- 引用工具數值時改寫或四捨五入後當作原值 → 該數值不採計
- 風險表的「影響的訊息」欄留白 → 退回
- 以工具輸出宣稱已完整驗證 → 該宣稱作廢（參照涵蓋率 7/34）
- 只交模擬圖，沒有指出失去的訊息與元件座標 → 該筆不採計
- 把單一色覺差異型態描述成所有閱聽人的視覺 → 該主張作廢
- 修正仍只依靠另一組顏色，沒有文字、形狀、圖示等冗餘線索 → 未通過
- 工具結果沒有原始輸出、版本或對應 token ID → 該數值不採計
