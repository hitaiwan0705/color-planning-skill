# W14｜色覺差異與可及性

## 這一週在解什麼問題

色彩可以強化訊息，也可能讓部分閱聽人失去訊息。可及性不是把畫面「變醜」，而是確保狀態、文字、控制元件與資料差異不只靠一條脆弱的色彩通道。

## 一、三個問題分開檢查

1. **文字對比**：WCAG 2.2 SC 1.4.3，檢查文字與背景。
2. **非文字對比**：SC 1.4.11，檢查必要圖形、邊界與控制元件狀態。
3. **顏色使用**：SC 1.4.1，檢查顏色是否是傳達訊息、動作或區別的唯一方法。

對比數值通過不能證明 SC 1.4.1 通過。紅／綠狀態即使對比足夠，若沒有文字、圖示、形狀或位置線索，仍然只靠顏色傳達。規範原文見 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)。

## 二、色覺差異不是單一濾鏡

色覺差異有不同型態與程度；模擬圖只是風險探測，不是任何人的真實視覺替身。`color_audit.py` 的 cvd 輸出可幫助找出候選衝突，但最終仍需人工檢查訊息是否有非色彩線索。

不要寫「色盲看不到顏色」或用單一模擬代表所有人。紀錄應指出：哪兩個 token 在哪個情境難以區分、失去哪個訊息、加入什麼冗餘線索。

## 三、P5 稽核步驟

1. 以 W13 原始版面與第一次輸出建立元件清單。
2. 執行文字／非文字對比稽核，保留工具 JSON 與版本。
3. 另做 SC 1.4.1 人工檢核：移除色相差異後，狀態是否仍可辨識。
4. 查看 cvd 情境輸出，列出失去區辨的 token 組。
5. 提出至少一個非色彩修正：文字、圖示、形狀、線型、位置或圖樣。
6. 回到訊息目標，確認修正沒有製造新的閱讀層級問題。

## 失敗條件

- 用對比數值宣稱 SC 1.4.1 已通過
- 只交模擬圖，沒有指出失去的訊息與元件座標
- 把單一色覺差異型態描述成所有閱聽人的視覺
- 修正仍只依靠另一組顏色，沒有文字、形狀、圖示等冗餘線索
- 工具結果沒有原始輸出、版本或對應 token ID
