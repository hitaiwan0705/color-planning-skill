## 這一週在解什麼問題

你手上有一張自己印的樣本，和一份說它應該長什麼樣子的規格。
今天要回答一個客戶遲早會問的問題：

> **「這樣算對還是不對？」**

「我覺得還可以」不能收錢。**驗收需要一個數字，而那個數字要能被對方重算出來。**

今天同時做兩件事：用眼睛在標準條件下看（S7），用儀器量（S8）。
兩者的結果放在一起，才構成完整的驗收證據。

### 容差是傳播決策，不是儀器規格

ΔE00 ≤ 2 不是從儀器手冊抄來的。它是一個**取捨**：

| 容差訂得太緊 | 容差訂得太鬆 |
|---|---|
| 實體接觸點做不出來，或成本上升到不值得 | 辨識、區隔、警示功能開始失效 |
| 每一批都要重印 | 客戶看得出來，但你的報告說合格 |

**所以容差要對應到功能，不是對應到色。** 寫法：

> 主色在包裝正面負責辨識，容差 ΔE00 ≤ 2.0（D50、燈箱、與標準色票並排比對）；
> 同一主色在內頁背景負責情緒定調，容差 ΔE00 ≤ 4.0（同條件）。

同一個色，兩個容差，因為它在兩處負責的功能不同。
**這一句就是這學期規範書和一份色票清單的差別。**

### 跑站規則同 W13

分組輪流，每站當場簽核（計入參與分），簽核不是交件。
缺該站簽核，該站產出檔不被採認；有簽核但交不出產出檔，該站仍為未完成。

## 一、S7：標準燈箱觀察

### 為什麼要在燈箱裡看

不是因為燈箱的光「比較正確」，是因為**燈箱的光是可指定、可重現的**。

你在教室日光燈下判斷、客戶在辦公室 LED 下判斷、廠商在車間金鹵燈下判斷——
三個人得到三個結論，而且誰都無法重現對方的條件。
燈箱把這個變數固定住。

> **設備閘門**
> - 本課燈箱具備 **D50 與 D65**，兩者皆可使用
> - **型號等級尚未以機身銘牌核對**，任何報告不得宣稱其為特定等級，
>   紀錄一律寫「型號待核對」
> - 螢光燈管種類未確認，**不得假設 TL84／CWF／U30 存在**；
>   依賴賣場光源的觀察一律標 `<!-- BLOCKED: 待設備確認 -->`

### 觀察程序

1. 樣本放入燈箱，**背景使用中性灰**（不要用白色，crispening 會影響判斷）
2. **適應十分鐘**。不是形式——W11 已經證明適應狀態會改變判讀
3. 依 W12 的五欄格式逐欄登錄
4. **D50 與 D65 各做一次**，兩者分開記錄，不要取平均

### 為什麼兩種光源都要做

如果同一對顏色在 D50 下相配、在 D65 下不相配，
那就是**同色異譜**——而這件事儀器的單一數值不會告訴你。

這是本課唯一能在已確認設備下做的同色異譜觀察。
把握它，因為它是這個現象最直接的證據。

## 二、S8：儀器量測

### 程序

沿用 W06 的完整流程：白板校正 → 量測 → 同一點三次取平均 → 記錄離散程度。

**量測條件表四欄不得留白**：光源／照明體、量測幾何、儀器型號、量測日期。

### 這一站要量什麼

| 對象 | 目的 |
|---|---|
| 樣本上的每一個色塊 | 與 design token 的目標值比對 |
| 媒材空白處 | 記錄媒材白，它是所有偏色的共同底 |
| W03 的原始色票（若為實體） | 建立參考 |

**媒材白最常被跳過，但它解釋了大部分的整體偏色。**
如果媒材白本身偏黃，樣本上所有顏色都會被那個底拉走——
這不是輸出設定的問題，改設定改不掉。

### ΔE00 報告

```bash
python3 tools/color/scripts/color_audit.py --pair "#目標" "#實測" --json
```

報告必須註明 **CIEDE2000**，不得與 CIE76 混用。
容差由你自己指定，但**必須寫出採用該門檻的理由**——
沒有理由的門檻不是判準。

## 三、把觀察與量測放在一起判讀

這是本週真正的技能，也是最容易做錯的地方。

### 三種情況，三種處理

| 情況 | 意思 | 該做什麼 |
|---|---|---|
| 儀器超標、眼睛也覺得不對 | 一致 | 修正，方向由五欄屬性指出 |
| 儀器在容差內、眼睛覺得不對 | **落差** | 歸因：是背景？適應？色貌現象？還是容差訂得不合用途？ |
| 儀器超標、眼睛覺得可以 | **落差** | 歸因；並檢討容差是否過嚴 |

**第二和第三種才是本模組的重點。** 它們是「儀器說一樣、人說不一樣」的具體形態。

### 一個實務上的關鍵判斷

當儀器與眼睛不一致時，**不要急著相信其中一個**。
先問：這次觀察的條件，和你訂容差時假設的使用條件，是同一個嗎？

- 容差是依「燈箱下近距離比對」訂的，但實際使用是「展場三公尺外」→ 容差太嚴
- 容差是依「單獨觀看」訂的，但實際使用是「與標準色票並排」→ 容差太鬆

**容差要跟著用途走。** 這一點在交付物裡要寫清楚。

## 四、本站實作：燈箱觀察與量測對照

### 這一週要新增什麼

| 步驟 | 內容 |
|---|---|
| 1 | D50 與 D65 下各一份五欄屬性登錄 |
| 2 | 完整量測條件表與 ΔE00 報告 |
| 3 | 每一色標出屬於上表三種情況的哪一種 |
| 4 | 落差的歸因，附排除理由 |
| 5 | 判斷任務參數紀錄：觀察者人數、呈現順序、重複次數、參考條件 |
| 6 | **逐項容差**：對照表上每一項功能各訂一個 ΔE00 容差，並寫出採用理由 |

### 關於第 5 項

如果你請同學一起看，就構成一個小型的判斷任務。要記錄：

- **觀察者人數**：一個人的判斷不能代表任何人以外的人
- **呈現順序**：先看的和後看的會互相影響
- **重複次數**：同一個人看兩次結果一致嗎
- **參考條件**：有沒有給參考樣本，給了哪一個

**這四項不是形式。** 沒有它們，你的觀察結果無法被任何人重現，
也就不能寫進報告當證據。

## 失敗條件

- 量測條件表任一欄留白 → 該筆量測不成立
- D50 與 D65 取平均 → 該筆作廢，兩者必須分開
- 未量媒材白 → 整體偏色無法歸因，退回
- 容差無採用理由 → 該門檻不採計
- 全部功能共用同一個容差而未說明理由 → 退回；不同功能對色差的耐受度不同
- 容差未對應到任何一項傳播功能 → 該門檻不採計為 ASSIGN-04 的證據
- 以目視代替 ΔE00 → 該數值不採計
- 宣稱燈箱為某特定等級 → 該段作廢
- 判斷任務參數缺項 → 該次觀察不得作為證據引用
- **觀察者紀錄含姓名或學號 → 立即退回**。一律使用匿名代碼
- 燈箱紀錄沒有模式、背景、距離或適應時間 → 該筆不成立
- 只因人眼與儀器不一致就刪除其中一條證據 → 未通過。**不一致本身就是資料**
