## 這一週在解什麼問題

規範書的價值不在頁數，而在下一位操作者遇到媒介落差時，知道該維持什麼、能改什麼、如何驗收。本週以一次受控修正與再輸出完成最後驗證，將失效點、容差、替代方案與檔案索引編成可交接的系統。

## 本週學習目標

1. 以「假設—單一變更—預期—結果」完成一次可歸因的修正。
2. 比較修正前後的量測、觀看與訊息功能證據。
3. 為每個失效點指定修正、繞過或接受限制的處置。
4. 編製可由陌生操作者執行與驗收的跨媒體規範書。

## 知識群與關鍵詞

| 知識群 | 關鍵詞 | 核心判斷 |
|---|---|---|
| 受控修正 | hypothesis、single-variable change、prediction、result | 結果能否歸因到這次變更？ |
| 前後驗證 | baseline、comparison、version、traceability | 改前改後是否使用同一基準？ |
| 失效處置 | correction、workaround、accepted limitation、fallback | 功能掉落時，下游要怎麼做？ |
| 規範交接 | rule、tolerance、exception、evidence index | 陌生操作者能否執行並驗收？ |

## 二、S9：一次只改一項

先填完整修正卡，再動檔案：

| 欄位 | 問題 |
|---|---|
| 問題 | 哪個 token 在哪個接觸點失去什麼功能？ |
| 證據 | 哪一筆觀看或量測資料支持？ |
| 假設 | 最可能機制是什麼？排除了什麼？ |
| 動作 | 這次只改哪一個色值、設定、媒材或冗餘線索？ |
| 預期 | 哪個指標應改變？哪個應保持不變？ |
| 結果 | 實際結果是否符合預期？ |
| 決策 | 採用、撤回，或保留為限制？ |

輸出工具由需求決定。操作前核對尺寸、媒材、描述檔、軟體版本與安全程序；某項功能不可用時，改用功能等價方案並記錄差異，只影響該步驟，不推翻前面已成立的規格工作。

## 三、前後對照與失效點結案

修正前後必須並排：版本、唯一變更、量測結果、觀看條件、色貌判讀與傳播功能。未改項目若也變動，要標示為批次變異、知覺交互作用或尚待查證，不能藏起來。

每個失效點只可用三種狀態結案：

1. **已修正**：功能恢復，附修正與驗證證據。
2. **以替代方案繞過**：色本身不承擔全部功能，指定文字、形狀、位置或媒介版本。
3. **接受並載明限制**：寫明失效條件、風險與下游因應。

「接受限制」不是放棄，而是防止下游在未知條件中誤用。

## 四、規範書最小結構

1. 訊息目的、閱聽人與三個接觸點。
2. token 名稱、角色與不可互換關係。
3. 各媒介的色彩空間、描述檔、轉換與檔案格式。
4. 媒材、輸出與觀看條件。
5. 文字、非文字與顏色使用的可近用規則。
6. 各功能的容差、驗收方法與超標處置。
7. 失效點結案、替代方案與已知限制。
8. 九站證據索引、版本歷程、來源、AI 與權利揭露。

### 陌生操作者測試

交換規範書。接手者不得詢問原作者，只能依文件完成三項任務：找到指定 token、選出正確接觸點規則、說明超標後的處置。把卡住的位置記入「交接缺口」，原作者據此修訂。

## 學習證據與評量角色

S9 簽核屬參與證據；受控修正、前後驗證、結案清單與規範書屬 ASSIGN-04 專業能力證據。反思需指出一項原先判斷被後續證據推翻的過程；前週原始紀錄保留，不回頭改寫。

## 學習工作量

- 課內：120 分鐘完成證據回看、修正、驗證、結案與交接測試。
- 課外：約 180–240 分鐘整理定稿、索引與缺檔清單。

## 失敗條件

- 同時改多項變因，無法判斷何者造成結果。
- 修正卡缺假設、預期或結果，或覆寫第一版與原始量測檔。
- 任一失效點沒有結案狀態；接受限制卻未寫下游因應。
- 規範書無法讓陌生操作者找到規則、例外、檔案與驗收方式。
- 用後站結果反推補寫缺失的前站條件。
- 缺站別簽核或有簽核但交不出產出檔。

## 本週重點整理

1. 受控修正一次只改一項，才能讓經驗被重作與移轉。
2. 規範必須同時寫正常規則、容差、例外與失效處置。
3. 交接品質以陌生操作者能否找到、執行與驗收為準。
4. 限制與缺檔要被誠實索引，不能用後來資訊回填成完美歷程。
